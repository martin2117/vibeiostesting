# BUG-001: Password Input Renders Plaintext Characters Instead of Secure Masked Text

**Severity:** High — Security/privacy vulnerability exposing user passwords on screen.
**Framework:** Appium / XCUITest (Maestro cannot assert secure text entry)
**Element Identifier:** `login-password`
**Cross-Build Status:** Reproduces on both SwiftUI & React Native
**Blocks Other Tests:** No

### Environment
- **Build Type:** SwiftUI (`com.techshop.ios`) & React Native (Expo)
- **Build Variant:** Broken
- **iOS Version:** iOS 26.5 / iOS 18.x
- **Simulator / Device:** iPhone 17 Pro Simulator
- **Framework & Runner:** XCUITest (xcodebuild) / Appium Python Client (pytest 8.4.2)

### Steps to Reproduce
1. Launch the app fresh on a clean simulator.
2. Observe the unauthenticated Login screen.
3. Tap on the Password input field (`login-password`).
4. Type `password123`.
5. Inspect the rendered text on screen and the element accessibility traits.

### Expected Result
The password field is instantiated as a secure text field (`SecureField` in SwiftUI / `secureTextEntry={true}` in React Native / `XCUIElementTypeSecureTextField` in accessibility hierarchy). Typed characters are masked with bullets (`•••••••••••`) and plaintext is hidden from the UI hierarchy.

### Actual Result
The password field is a standard plain text field (`TextField` / `XCUIElementTypeTextField`). The password `password123` is rendered as unmasked plaintext on screen and exposed in the accessibility tree.
